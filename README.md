# Administrador de edificios

Propuesta de proyecto
Desarrollo de una aplicación web en la nube para la administración automatizada de edificios.
Público objetivo: Juntas administradoras de edificios y barrios.
Funciones:
Registro de transacciones (ingresos y egresos)
Inventario
Cálculo de cuota mensual y Visualización historial de pagos.
Biblioteca de documentos (reglamento, estatutos, etc.) y Registro de actas
Notificaciones (por correo electrónico incluso).
Registro de transacciones:
Base de datos simple. Se tiene un registro de los ingresos (cuotas de cada propietario) y los egresos del edificio. Los egresos pueden ser fijos (se activan por un periodo de tiempo) o variables (registrados en cada mes). Los administradores de la junta pueden visualizar y modificar cada registro. Los usuarios solo pueden visualizarlos. Como opción, se puede habilitar el escaneo del recibo de cado gasto realizado.
Inventario:
Funcionalidad opcional. Se tendría un registro simple de los activos comunes del edificio. Se puede incluir la opción de foto del producto, así como el escaneo de facturas, boletas de venta, etc. de cada producto (para acceso a reparación o reclamo, por ejemplo).
Cálculo de cuota mensual y emisión de reportes:
Con base en los ingresos y gastos ingresados. El sistema debe ser capaz de generar u recibo mensual con el monto que le corresponde pagar a cada departamento. El mismo debe incluir un resumen de los gastos e ingresos comunes.
Ingresando al sistema, cada usuario podría revisar el historial de recibos, así como el estatus de los mismos (pagados o no pagados)
Biblioteca de documentos
La web debe permitir generar una sección con acceso a los documentos comunes como:
Estatutos
Reglamentos
Contratos del personal,
etc.
Asimismo, se puede incluir el registro de actas del edificio, para las decisiones comunes, las cuales pueden descargarse (evaluar si las actas deben escanearse para registrarlas con firmas). Estos documentos son de acceso común a todos los miembros del edificio.
Calendario y portal de noticias
El calendario incluye eventos, recurrentes o no, para todo el edificio. Entre ellos pueden incluirse el rol de limpieza, o avisos de mantenimiento de ascensores, por ejemplo. En el portal se pueden incluir anuncios internos, los que pueden ser generados por cualquier usuario (el administrador del edificio puede tener acceso de moderación)
Notificaciones
El sistema debe permitir las notificaciones a los usuarios y administradores, tanto al ingresar al sistema, como por correo electrónico (de ser activado).
Modelo de negocio:
Cada junta directiva registra su edificio en la plataforma (un administrador podría registrar múltiples propiedades).
Se tiene un pago mínimo por propiedad + un monto fijo por cada usuario con acceso a la plataforma.
La plataforma es una nube común para todos los usuarios registrados.
Un mismo usuario podría visualizar múltiples propiedades, si es estas usan el sistema (ej: casa urbana y casa de playa).
El pago es una suscripción mensual.
